"Linear" and "nonlinear" here are Symmetrix engine/model families, not linear-vs-nonlinear MLIPs:

The upstream linear Kokkos engine cannot load MACE_Nonlinear at all. MACEKokkos::load_from_json rejects it at mace_kokkos_model.cpp:165-167 with:

MACE_Nonlinear JSON must be loaded through the nonlinear MACE Kokkos evaluator,
not legacy MACEKokkos.

The naming "H1" is a collision: in the linear engine H1 is the first-interaction hidden state; it is not the MACE-MH-1 model family. No PolarMACE layer can be delegated to MACEKokkos, and the linear engine's mpi_message_passing path cannot be reused for PolarMACE.

1.3 MH-1 fast-path status

PolarMACE cannot use the current MACE-MH-1 direct/JIT fast path. The engine's family descriptor rejects it with:

MH-1 node, edge, and hidden irreps are inconsistent.

This is architectural, not an export defect. The original checkpoint has the same architecture as the JSON. The four deviations from the admitted MH-1 family are:

  1. second interaction uses 128x0e+128x1o edge features instead of the first interaction's 512x0e+512x1o;
  2. second interaction keeps a vector component in hidden_irreps (512x0e+512x1o instead of scalar-only 512x0e);
  3. second product returns 512x0e+512x1o instead of scalar-only 512x0e;
  4. second readout is NonLinearBiasReadoutBlock (with a learned linear_mid stage) instead of NonLinearReadoutBlock.

A v3 MH1_UVU contract is present in the JSON, but it covers only the per-interaction UVU tensor products and does not establish v4 node-program family compatibility. The v4 contract generator fails first at products[1] output irreps are outside the MH-1 support matrix. Re-exporting (Route A) cannot fix this without changing the learned function; relaxing only the gate (Route C) is numerically incorrect and is also not a speed win. See docs/design/MH1_FASTPATH_FEASIBILITY.md for the full rejection chain and the staged B1-B4 route assessment. No speedup from MH-1 is claimed anywhere in this report.

4. Findings

4.1 Cost structure: backbone plus polar non-k kernels

Completed measurements give a consistent picture:

  • 128 atoms, same model: backbone-only 87.24 ms -> full 183.50 ms. The polar layer adds 96.26 ms (52.5% of the full eval, 2.10x).
  • 432 atoms, N2/33 A, same model: full 475.883 ms/step vs polar-off 190.738 ms/step. The polar layer adds 285.145 ms (59.9%); the backbone accounts for 190.738 ms (40.1%).
  • Stage profile at 128 atoms (polar_profile_8eval_v29.log, representative uncontended eval): backbone + stage 1 ~36.6 ms; polar forward pipeline ~20 ms, of which the k-space Coulomb stage is ~14.0 ms; reverse/replay and node forces ~53 ms. The k-space slice is therefore only ~7.6% of that eval, while the nonlinear MLP/UVU/replay kernels dominate the polar cost.

Long-range share. The full polar layer is ~60% of the 432-atom step in the completed coarse ablation. The finer figure that the ongoing profiling round attributes to the k-space/long-range slice, ~20% of the 432-atom step, is an in-flight estimate: the dedicated 432-atom stage profile (polar_profile_n2_33a.py) had produced no output at the evidence cut-off. Treat the ~20% as provisional until that JSON/report exists; the 60% full-polar ablation and the 40% backbone share are directly measured.

Bottleneck: the nonlinear backbone (roughly 40-48%) plus the polar non-k kernels (UVU/MLP reverse, replay, local-electron, node forces). Optimizing only the k-space Ewald/RBE stage cannot remove most of the cost.

4.2 MH-1 is architecturally blocked

The rejection is a family-shape check, not a missing export or a flag. The model's second interaction differs on edge channels, hidden irreps, product output, and readout class; the checkpoint matches the JSON exactly. Route A (re-export) is infeasible without retraining/distillation, and Route C (relaxing only the gate) would run unprepared conditioned-MLP tables and is numerically wrong. The staged route estimates are engineering estimates, not measurements:

Route Scope Estimated speedup Effort
B1 family analysis + pair conditioning + generic streamed, FP32 enablement ~0.5-1.0x (not a speed guarantee) 5-8 days
B2 B1 + v4 contract + JIT host/device artifacts, polar materialized target 1.5-3x backbone, ~1.2-1.5x full model +15-25 days
B3 full polar direct/JIT up to ~1.5-2x full model +10-20 days
B4 LAMMPS direct/JIT wiring required to change the measured LAMMPS timings +10-15+ days

None of these estimates is included in the measured tables above.

4.3 RBE and 1-hop are rejected by the force gate

Both are genuine performance ideas, and both fail the minimum-accuracy rule:

  • RBE: excellent statistical behavior (slope -0.49885, unbiased, bitwise same-seed reproducibility) but RMS_F 1e-2 to 4e-2 eV/A, i.e. 100-400x the 1e-4 eV/A force gate.
  • 1-hop ghost: 2.86x faster than exact 2-hop, but dE 7.94e-5 eV (1.6x over the 5e-5 eV tolerance) and max dF 4.116e-3 eV/A (41x over the 1e-4 eV/A gate).
  • Exact 2-hop is the only MPI mode that passes, and it is 28.1x slower than 1 rank on one GPU.

4.4 One GPU means MPI does not speed up

All MPI timings above were taken on one shared A100. The exact 2-hop ghost graph has ~20x more edges than the 1-rank graph in the 14.7 A box, and the 2-hop workspace exceeds a single card at 4 ranks (4.5-6.9 GiB per block). The upstream linear H1 message passing is also 3.38x slower at 2 ranks on the same GPU. MPI is a functional/correctness milestone, not a speedup, until per-layer feature exchange and multiple GPUs are available.

Sample-blocked scalar kernels keep the per-output source accumulation order and coalesce weight reads (e3nn_kokkos.cpp:420-437, :1214-1231). On the 128-atom full model in LAMMPS: 184.06 -> 165.99 ms/eval (1.11x), medians of two independent 12-evaluation rounds. Bitwise equality (max abs diff 0.0) was verified on synthetic small/wide cases and on the full model tensors (1,245,184 values), plus a NumPy scalar reference.

5.4 MPI H1 message passing

2-rank H1 parity on the 128-atom NH3 box: dE 2.91e-11 eV, max dF 1.41e-15 eV/A; 20-step NVT stable (no lost atoms, final state matches 1 rank to 9.8e-15 A and 4.7e-14 eV/A). Wall time 1600.5 ms vs exact 2-hop 5155 ms (3.22x faster), but 8.7x slower than the optimized 1-rank path (183.6 ms) on one shared GPU. Fixed in this round: local-receiver graph construction, ghost force accumulation/communication, Kokkos polar pack/unpack branches, 1-rank H1 mode retention, comm_forward/comm_reverse flags, and double-counted ghost adjoint seeds.
