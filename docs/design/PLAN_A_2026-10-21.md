# Plan A (2026-10-21) — next performance/capacity line

**Status:** active plan.  Plan B-30ms is the accepted baseline.
**Baseline:** 30.56 ms/eval at 128 NH3 (238.8 µs/atom), full PolarMACE, FP64,
one A100-80GB, binary `f0d3f05a…`; 224.1 µs/atom at 1,296 water atoms (older
accepted 1,296 value, Plan B-30ms not re-measured there); 5,184 atoms OOM.

## 0. Non-negotiable contract

- FP64, exact physics, full gate suite: module 5–8, 32/32 end-to-end,
  1-rank and 2-rank LAMMPS parity, repeated evaluation (3× `run 0`).
- No un-gated branch may be pushed to `master`.  Work stays on a feature
  branch or in the gitignored `bench/` tree until the gates pass.
- Commit messages must not contain a `Co-Authored-By: MatOS Opus …` trailer.
- Every reported number must name atoms, precision, path, binary hash, and
  whether it is measured or projected.

## A0. Close Plan B-micro (current blocker)

**Finding (2026-10-21):** `bin/lmp_micro` (`REV=1, FWD=0`) crashes with
`cudaErrorIllegalAddress`; `REV=1, FWD=1` works and gives the same PE as off.
Root cause: the reverse-only `else` branch dereferences the host
`scalars_host` inside a `KOKKOS_LAMBDA` (see
`bench/plan_b_micro_2026-10-21/debug/ROOT_CAUSE_REV.md`).

- **Product path:** `off` vs `both` (`REV=1, FWD=1`).
- **Fix for diagnostics:** copy `scalars_host` to a 6-element device view, or
  gate `fukui_dev_rev` on `fukui_dev_fwd`.
- **Acceptance:** repeat-eval (PE identical ×3, max dF ≤ 1e-15), 1-rank parity,
  A/B vs `f0d3f05a`; keep only if the measured saving is > 0.2 ms and no gate
  moves.  Otherwise default `REV=0` and move on.

**Update 2026-10-21:** `both` repeat-eval PASS:
PE `-49242.45641531493` ×3, dPE 0, max dF `6.4e-16` / `8.9e-16`.
`revonly` root cause documented in
`bench/plan_b_micro_2026-10-21/debug/ROOT_CAUSE_REV.md` (host
`scalars_host` dereferenced inside a `KOKKOS_LAMBDA`).

**Measured result:** base 30.6016, `both` 30.6033, `revonly` 30.5760 ms/eval
(median of 2×12); all within 0.1 %.  **A0 is a null result; do not merge.**
See `docs/results/MICRO_FUKUI_DEV_2026-10-21.md`.

## A1. UVU tile at 1,296 (primary 1,296 speed)

Sandbox: `bench/qiuyong_pclone/` (`ab_uvu_opt.py`, `sweep_tile.py`,
`parity_uvu_opt.py`).  Candidate binary
`external-repos/symmetrix-xl-opt1/manual-build/lmp`; main
`external-repos/symmetrix-xl/symmetrix/build-kernel-r3/lmp`.

- Same-binary interleaved A/B, 1,296-atom water, 2 rounds × 4 samples.
- Tile shapes: default, `32,32`, `64,32`, `64,64`, `128,32`.
- Acceptance: candidate > 1 % faster, 128-atom parity max dF ≤ 1e-10,
  repeat-eval stable, 1,296 parity.
- Expected gain from the initial screen: ~12–16 µs/atom.  Kill if the
  measured gain is < 3 µs/atom or parity fails.

**Preliminary 2026-10-21 A/B (1,296 atoms):** main `289.669 ms`
(223.51 µs/atom); UVU candidate `304.766 / 305.055 ms`
(235.16 / 235.38 µs/atom) in rounds 0/1.  The candidate is **~5 % slower**,
not faster.  Prior tile-shape sweep also measured 305–310 ms.  Treat A1 as a
likely negative unless the final round/parity says otherwise; pivot to A2.

**Port to main 2026-10-21 (PASS):** branch `plan-a-uvu-tile` from `e0a961d`,
only `mace_polar_impl.tpp` changed.  Baseline `lmp_main_e0a961d`
`290.196 ms` (223.92 µs/atom) vs candidate `lmp_uvu_tile`
`266.214 ms` (**205.41 µs/atom**), ratio **0.9174 (−8.26 %)**; 8 candidate
samples max 266.905 < 8 baseline samples min 289.379.  128-atom parity PASS
(dPE 0, max dF 5.55e-16), repeat-eval exact, 1-rank LAMMPS parity PASS
(dE 2.91e-11 eV, max dF 2.61e-14 eV/Å).  The patch's actual default is
`tile_n=32, tile_m=16` (the helper overrides the caller's 32,32); 32×32 is
0.39 % slower in the diagnostic.  Full module 5–8 / 32-32 / 2-rank gates are
in progress; branch is local and **not merged/pushed**.
Report: `docs/results/UVU_TILE_MAIN_1296.md`.

## A3. Tiled-edge for 5,184 (capacity, not a 1,296 speed claim)

- Design deliverable: `docs/design/TILED_EDGE_PLAN.md`.
- Acceptance: 5,184 atoms run on one A100-80GB, peak VRAM < 80 GB, parity vs
  the 1,296/2,592 reference where comparable, and no regression at 1,296/2,592.
- Tiling is expected to trade some throughput for memory; report both.
- Do not quote a 5,184 speed until it actually runs.  S1.1 already gives a
  working 5,184 at **19.21 GiB / 1084.25 ms**; tiled-edge targets 16.6 GiB and
  a smaller time penalty, but is not yet implemented.

## A5. RuNNer 2.0 transferable techniques

Deliverable: `docs/research/RUNNER2_TRANSFERABLE_TECHNIQUES.md`.

Use it for:
- QEq/plane-wave scaling intuition (O(N³) → O(N log²N); direct Ewald
  O(N^{3/2}) vs PPPM/plane-wave O(N log N)) — relevant at 5,184+, not at 1,296
  where Ewald is ~1.67 % of GPU busy;
- memory-management/tiling as the capacity lever;
- hybrid MPI/OpenMP scale-out lessons;
- committee computation sharing for high-throughput batch inference (not MD).

Do **not** build/run RuNNer as a speed baseline; its CPU/HDNNP numbers are not
like-for-like.
